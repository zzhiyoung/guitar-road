# Creator OMR 改造进展

**Creator 整体仍是实验测试功能，不保证识别准确性；所有模式的结果都需人工校对。** 2026-10-03 合并更新与发布验证见 [更新记录](RELEASE_NOTES.md)。以下保留此前开发过程的样本结果与验收边界。

更新：2026-10-02。用户已要求集成主程序，**Creator 已接入实验性五线谱/TAB pipeline**；此前原型的扩大样本出口和正式验收仍未完成。
开发范围和出口条件见 [开发计划](OMR_TAB_DEVELOPMENT_PLAN.md)。专辑管理与整曲播放沿用用户已验收的实现。

## 已交付

### 主程序实验集成（本轮）

- Creator 输入模式：自动、五线谱＋TAB、仅五线谱。组合谱先隔离 TAB，再调用 homr；未知数字、额外符号、小节数/时值/横向位置不一致时拒绝合并。“仅五线谱”不保留原指法，页面仅显示标准谱，避免把自动计算指法冒充原 TAB。
- `pipeline.py` 与独立子进程 `homr_geometry.py`：使用已测试的 homr 0.7.0 分割位置，关闭子进程的二次自动裁剪；按系统和小节核对几何位置与音乐事件，时值来自五线谱，弦号/品位来自 TAB。没有改写已安装的 homr 文件。组合谱导出单个吉他声部，保留原指法、八度转调和 MIDI 吉他音色；音高冲突逐条记录，草稿采用 TAB，仍需人工复核。
- 页面新增试听、暂停、停止复位，显示警告；处理中禁止替换输入。仅 Creator 对六弦输出启用五线显示适配，Practice / Song Player 默认行为未改。
- 三张原稿完整转换均通过 alphaTab 导入与 MIDI 检查：合计 48 个音的原弦号/品位、八分时值及发声音高与既有人工候选标注一致，每份单轨单谱表、2 小节，无重复发声。当前模型/裁剪下音高冲突为 3、2、2 处，与较早局部裁剪结果可不同，不能混为同一次测量。
- G7 扫描片段因拍号伪事件拒绝 TAB 合并，没有生成猜测文件；仅五线谱模式生成单谱表草稿。复杂片段、纯 TAB 仍不支持。
- 34 项确定性测试通过（新增 10 项融合/输出安全契约）；typecheck、隔离及主程序生产构建通过。浏览器验证原稿上传→识别→组合谱/仅 TAB/仅五线谱显示、试听启动/暂停/停止；标准谱确为五条线。实际扬声器音色、新文件 Guitar Pro 导入仍由用户验收。
- 下载收尾：原 Blob 下载的内置浏览器事件回执超时，改为无状态 POST `/api/creator/download`，用 HTTP 附件返回 XML，不写文件或数据库；校验请求、限制草稿 2 MB，并提供 UTF-8 文件名。HTTP 响应与识别草稿的字节哈希相同，中文下载名正确，错误请求返回 400。浏览器通过原创四音小样本的同类表单实际下载，落盘内容与 fixture 一致；临时检查页已删除。用户识别文件的 Guitar Pro 校对仍待验收。
- 更新主程序默认生产构建，旧 `.next` 留作本地备份；没有更改启动器、端口、Node 要求或构建标记，也没有创建歌曲/练习记录。截图和实际识别产物仅保留在本地临时测试目录，不进入 Git。
- 主程序 3000 API 再次验证原稿合并及实际 MIDI 一致，状态读回 ready / CPU；构建及 API 检查前后，对全部数据库/上传文件的哈希比对一致。

### 此前 P0–P2 原型记录

- `tools/omr/guitar_road_omr/regions.py`：检测五线谱和六线谱、配对系统、定位小节边界；保留五线谱诊断裁剪。新增长谱线的小幅统一倾斜纠偏，并记录原图与分析图坐标变换。基于谱线几何，不使用三个样本的固定坐标。
- `tab_parser.py`：自写 TAB 定位/弦归属逻辑，结合可选本地 RapidOCR 数字识别；保留原弦号、品位、位置、候选和待核对原因。不能识别的数字保持未知，不补成空弦。
- `inspect-tab`：独立检查 CLI，输出 JSON 和可选诊断图；不提供时值、不生成 MusicXML、不创建歌曲或练习记录。现有 `status`、`recognize` 接口保持兼容。
- 原创 MusicXML 兼容性 fixture、alphaTab 模型/MIDI 检查、24 项确定性测试及可重复的原创字体 OCR 检查脚本。
- 可选依赖与许可证说明；未安装、升级或打包 OCR 模型，公共仓库不含教材截图、实际识别产物或用户数据。

## 实测结果

| 检查 | 当前结果 | 结论边界 |
| --- | --- | --- |
| 三个原始教材片段 | 48/48 弦号和品位与人工候选标注一致；各片段 2 小节、8+8 事件；无待核对事件 | 同类样本已用于调参；标注尚未由用户独立确认，不代表泛化准确率 |
| 原创 Arial 图 | 16/16；覆盖 0、1、10、11、12、20、24 品、六弦与两个系统 | 合成几何图，不是实际完整乐谱或独立教材验收 |
| 原创 Times / Segoe UI 图 | 本轮各 16/16，无待核对事件；此前各 14/16 的失败证据保留 | 三种字体都已参与诊断/调参，不能作为留出集准确率 |
| 确定性测试 | 24 项通过 | 增加纠偏、原图坐标映射、窄数字、邻弦片段与拍号分类检查；不替代真实 OCR 测试 |
| alphaTab 1.8.4 导入与 MIDI | 单轨单谱表；2 弦 5 品与 1 弦 0 品保留原指法；吉他记谱八度正确；MIDI 发声为 E4、E4、D5、E2，各一次 | 原创文件格式检查；Creator 页面显示切换和实际设备试听未验收 |
| Guitar Pro 8 原创 fixture | 用户针对上一轮四音导入/播放检查反馈“ok”，附图显示一个 Guitar 音轨和原 TAB 指法 | 此四音兼容性小样本获用户确认，不代表新识别文件或完整流程已验收 |
| 新增单音扫描片段：TAB | 首次因约 0.48° 倾斜无法定位；纠偏后 24 个音乐事件与人工候选标注一致，小节分组 16+8；另有 1 个疑似 C 拍号的未知候选 | 总候选数为 25，存在额外事件，完整样本未通过；不把 24 个正确事件写成整体 100% |
| 新增单音扫描片段：五线谱 | 自动诊断裁剪交给现有 homr 后，为单谱表、2 小节、24 个十六分音符及一个二分休止符；每小节 4 拍 | 仍有 1 处音高与 TAB 候选标注相差半音；没有融合或自动覆盖音高 |
| 新增复杂奏法/多系统片段 | 当前返回未配对 TAB 错误，没有音乐结果 | 第一系统的五线谱定位也未成功；不是已识别或已保留奏法，留作后续范围样本 |
| 新增纯 TAB 片段 | 明确拒绝：需要对应五线谱 | 纯 TAB 节奏及复杂奏法不在首版范围，没有伪造节奏 |
| 核心应用验证（上一轮） | typecheck 与隔离 production build 通过；首页、曲库、统计、导入、Creator 页面均返回 200；没有 OMR 的隔离环境正常提示不可用 | 本轮只改可选 Python 工具与文档；页面服务检查不代表练习播放的浏览器或音频回归验收 |

字体检查首次发现短符干漏检、OCR 把弦线当成数字边缘的问题；收紧图块并调整符干定位后改善。
本轮改用字形中央区域、尺寸与裁剪边缘连续性检查，允许有边界的窄数字，同时排除穿越弦线的细长符干、端点及邻弦数字片段。
中间版本曾在旧教材样本引入虚假“1”候选，已修复；最终三个旧样本重新达到 48/48，并通过三种原创字体检查。失败版本与产物均留在本地，不能只保存最终成绩。
新增单音扫描片段的拍号候选仍无法可靠分类，保留未知和警告，不因数量接近就静默删除或强配对。
三种字体和新增单音图都已用于本轮调试，因此仍需新的独立真实样本评测。

## 未完成与下一步

以下为集成前的阶段记录；本轮已以实验方式完成单音组合谱的融合、页面与播放入口。后续仍需修复拍号伪事件、扩展独立样本及多系统验证，并完成用户对新文件的 Guitar Pro/实际设备验收，之后才能扩大正式支持范围。

1. P0：原创文件的 alphaTab / Guitar Pro 8 小样本检查已通过。alphaTab 导入的六线配置在切换标准五线谱时还需页面适配验证；新识别文件仍须单独验证。
2. P1：已验证新单系统片段的“自动纠偏/裁剪 → homr”局部通路，尚未组合为新 pipeline；需验证多系统的升降号、附加线、页边信息及裁剪结果。
3. P2：三种字体窄数字检查通过，但新扫描图仍有拍号伪事件；先解决页首符号与音乐事件区分，再扩大真实版式、多系统和独立样本评测。当前出口条件尚未全部满足。
4. 通过上述条件后执行 P3：按系统、小节和横向位置对齐五线谱时值与 TAB，保留冲突记录；再执行 P4 接入 Creator 输入模式、播放控件和质量提示。

当前工具不处理纯 TAB 节奏、和弦、奏法或手写谱。对需要明确符干的布局进行检查，文件上限 20 MB / 2000 万输入像素，纠偏后最多 2200 万像素，谱线间距 4–26 像素，最多 8 个系统、每系统 128 个候选事件。仅尝试 3° 内一致倾斜纠偏，已验证真实约 0.48° 及合成 +0.5° / ±1.5°；不处理透视或弯曲页面。OCR 分数不是校准后的正确概率。独立 CLI 尚无服务级超时，自动化使用应由父进程限时；未来 API 接入沿用现有时间限制。

候选 bbox、事件 x、谱线和诊断图片使用纠偏后的 `analysis_image` 坐标。JSON 的 `image_geometry` 给出 `source_to_analysis` / `analysis_to_source`，用于映射到原图；不能将分析图坐标直接当作原图坐标。原图没有覆盖或改写。

## 主程序使用与隔离（此前原型轮次）

此前原型轮次没有重启正在运行的主程序、改写主数据库、覆盖 `.next`，或更改 Node、端口及启动器。当前集成轮次已保留旧构建备份并更新 `.next`，启动 3000 主服务；Creator 不写入练习数据库。
构建与页面检查使用独立应用副本、临时数据库/文件目录和临时服务端口，检查后已停止该测试服务。
Windows 跨盘依赖链接导致的两次隔离构建失败已通过实体依赖副本解决；失败证据保留在本地。
上一轮主服务的 OMR 状态读回为 ready / CPU。本轮结束时只读探测本地 3000 端口未连接；没有启动、停止或重建主服务。
上述隔离说明记录的是此前原型轮次；本轮已按用户要求接入 Creator 并更新默认生产构建。原启动器可以继续使用，本机 OCR 会占用 CPU。
